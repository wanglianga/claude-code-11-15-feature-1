# 生鲜订货决策系统

面向叶菜/根茎/鲜肉等短保生鲜的门店订货系统。四个各自持有状态的模块靠**不可变版本**串联：

```
需求还原 → 分位预测 → 门店改量 → 收市复盘
   ↑__________（复盘决定哪些样本允许回流）__________|
```

- **需求还原**：按门店/品类/到货日，把缺货时段、断货标记、售罄时点、有货时段销售速率整成**截断观测样本**；
- **分位预测**：基于还原样本生成带**特征快照**的建议版本（临界分位 × 特征因子，向上取整到最小订货单位）；
- **门店改量**：店长只在该版本上改量、记原因码并确认订单；
- **收市复盘**：按订单版本归因实销、报损、缺货损失，决定哪些样本回流需求还原。

任一模块重算都不改写下游已确认的记录。

其上扩展 **多期库存结转与临期折价子系统**（同样以不可变分组规则版本串联）：

```
批次台账 → 结转引擎 → 折价治理 → 历史复盘
（按保质期分组登记） （跨日滚存+成本归属） （折价需求单列） （按当时版本重算未确认区间）
```

- **批次台账**：按保质期分组登记在库 / 在途 / 临期数量与批次到期日；叶菜当天清、鲜肉可存三天、根茎耐储；
- **结转引擎**：跨日把剩余库存滚到次日并裁定成本归属（归原到货日 / 归结转日，写进分组规则版本）；
- **折价治理**：临期折价计划与由此回升的销量单独标记为**折价需求**，不当真实需求回喂模型；
- **历史复盘**：分组规则调整后按**当时版本**重算历史区间的未确认部分，已确认订单不追溯改写。

## 写死的取舍（口径中途不能换）

| 取舍 | 规则 | 代价/后果 |
| --- | --- | --- |
| 训练目标 | **不直接拿实销当需求**。缺货日实销被货架截断，先还原成截断观测（有货时段速率 × 全天营业时长）再建模 | 门店必须回传断货标记；标记缺失时页面只能**降级为保守估计**（实销为需求下界，不外推） |
| 复盘基准 | 复盘以**观测需求**（还原后需求）而非实销为归因基准，与训练口径一致 | 口径选定后中途不能换 |
| 建议量 | 临界分位 **τ = Cu/(Cu+Co)**（Cu=缺货单位损失含客流损失，Co=报损单位成本）。叶菜默认 8/2→**高分位 0.8**，根茎 2/2→**中位 0.5**；同品类不同门店允许覆盖（cost_params） | 不用期望值给数：期望掩盖尾部风险；单价比标定错会让历史订单损耗归因整体偏移，故 Cu/Co 随版本快照固化 |
| 取整 | 建议量**向上取整到最小订货单位**的整数倍 | 规则写入版本快照 `rounding=ceil_to_min_order_unit` |
| 版本 | 建议版本**不可变**：促销取消/降温/配送延误触发重算只产生新修订版本；店长已确认的订单版本原样保留，复盘按当时版本归因 | 历史版本只读可查 |
| 并发 | 店长确认与总部修订同时落库 → **按落库先后裁定**，另一方收到 409 冲突提示；同一到货日重复提交按**幂等键**并成一张建议表 | 数据库行锁 + 幂等键唯一约束保证 |
| 账实不符 | 库存与盘点对不上**以盘点为准**并留差异记录；**差异批次从训练样本剔除** | 否则系统库存会把需求还原污染掉 |
| 报损补录 | 次日补录的报损单落在窗口内（营业日次日 12:00 前）才触发**结转重算**；过窗的单独存档并说明出处 | 当日已锁定的建议量保持原样 |

### 多期结转与临期折价（子系统取舍）

| 取舍 | 规则 | 代价/后果 |
| --- | --- | --- |
| 库存模型 | 选**多期结转**而非单期模型。单期最省事（叶菜当天清确实够用），但鲜肉三天保质期会把同一批货在三个到货日各算一次；多期结转按批次滚存才不重复计数 | 前提是门店**按批次回传盘点**；少了批次盘点，账面库存会带偏需求还原 |
| 成本归属 | 结转成本归**原到货日**还是**结转日**写进分组规则版本（`costAttribution`）；规则版本不可变，改版生成新版本 | 规则一改历史毛利口径就分叉；历史区间需按当时版本重算（见「历史复盘」） |
| 保质期分组 | 分配规则版本：叶菜保质期 1 天（`carryoverAllowed=false` 当天清）、鲜肉 3 天（可结转）、根茎 7 天（临期 2 天）；到期日 = 到货日 + 保质期 − 1 | 批次登记时固化规则版本与到期日 |
| 账实不符（批次级） | 以**实物盘点**为结转基数；差额不进库存，**单独立账**（`inventory_adjustments`，待复核），该批次**剔除训练样本** | 账面与实物对不上时以盘为准，避免污染需求还原 |
| 幂等合并 | 盘点与结转按**（批次 / 营业日, 盘点时点）**幂等：同盘点时点重复上报不生成第二份结转；同批次号且数量/到期日一致重复登记幂等返回 | 重复上报不重复滚存 |
| 折价需求 | 折价回升销量 = 实销 − 基准量，按规则版本 `markdownUpliftRealShare` 拆成真实需求 / **折价需求**；折价需求写 `markdown_demand` 并把当日样本剔除训练 | 折价需求不当真实需求喂回模型 |
| 跨日补录（折价/报损） | 按**到达时点**判断：窗口内（营业日次日 12:00 前）重算；过窗部分注明来源另行归档，**已锁定的建议量不动** | 口径不追溯、不覆盖已锁定结果 |
| 规则改版后的复盘 | 按**当时版本**重算历史区间，**只重算未确认部分**；已确认订单不追溯改写（明细标 `skipped_confirmed`） | 加锁口径不可回写：新版本生效日不得早于今日 |
| 对账口径 | 批次台账、结转结果与复盘口径**按到货日逐项对账**（`reconciliation_grain=arrival_date`），对不上的批次单列交品类经理复核 | 差异不静默吞掉 |

## 技术栈

- 前端：React 18 + TypeScript + Vite + Zustand（三级筛选与建议表草稿状态）+ React Router
- 后端：Node.js 22 + Express + TypeScript + PostgreSQL 18（事务/行锁/唯一约束）
- 测试：Vitest + Supertest（62 项）

## 演示数据与推荐操作路径

空库启动自动写入：3 门店 × 11 SKU（叶菜/根茎/鲜肉，含 1 个无历史新品）、两版不可变保质期分组规则（v1 归原到货日 / v2 归结转日）、近 60 天截断观测样本（含售罄截断、断货标记缺失降级、盘点差异剔除、折价需求剔除四种形态）、朝阳门店昨日「建议→确认→复盘」完整闭环、多期批次台账（在库/在途/临期）、一次跨日结转（含批次盘点差异与独立账）、一张临期折价计划与折价需求拆分、一条跨 v1→v2 的未确认区间重算、按到货日对账差异、三门店明日建议表首版。

### 既有四模块

1. **建议与订货**（`hq` 登录）：选「降温超出预报」重算 → 生成 v2，v1 标记「已修订」且内容不变；
2. 同页（`store1` 登录）：在最新版本上改量、选原因码 → 确认订单；若总部先修订会收到冲突提示并自动刷新；
3. **收市复盘**：选昨天到货日 → 查看按订单版本归因的实销/报损/缺货损失（基准：观测需求）与**多期结转成本**；补录报损单（窗口内结转重算）、提交盘点（差异批次样本剔除）、**确认复盘**（锁定后不再被重算改写）；
4. **需求还原**：查看支撑到货日预测的近 7 日截断观测样本（截断/降级/剔除标记）。

### 多期库存子系统（建议按此顺序）

5. **批次台账**：看保质期分组规则（叶菜 1 天当天清 / 鲜肉 3 天可结转 / 根茎 7 天）、在库/在途/临期汇总；对某在库批次做**盘点**（填实盘数）→ 差异以盘为准、差额进「独立账」，同盘点时点重复提交幂等；可代门店**登记批次**（到货日晚于今日自动记在途，可点「到货」入库）；
6. **多期结转**：选昨天执行结转 → 叶菜清出、鲜肉滚存、成本按规则版本归属（v2 归结转日）；同一营业日+盘点时点重复执行幂等返回；下方**按到货日对账**，待复核差异可点「复核」；
7. **临期折价**：对临期批次建折价计划 → 录折价实销，折价回升里按规则拆出**折价需求**（不回喂模型）；切「次日 13:00（过窗）」再录一张 → 过窗归档、已锁定建议量不动；
8. **历史复盘**（`hq`）：选区间（默认近 7 天）→ 重算未确认区间，可见跨 v1/v2 的规则版本分叉、`已确认 · 不追溯` 明细、结转成本差与折价需求重算。

## API 概览

统一前缀 `/api`，除登录外均需 `Authorization: Bearer <token>`；冲突返回 `409 {error:{code,message,details}}`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/auth/login` | 登录 |
| GET | `/meta` | 门店/品类/SKU/成本参数/系统口径/规则版本 |
| GET | `/samples` | 需求还原截断观测样本（门店+品类+日期区间） |
| GET | `/suggestions` | 建议表 + 版本列表 + 当前版本明细 + 已确认订单 |
| POST | `/suggestions/generate` | 生成/事件重算（总部）；幂等键并表；已确认则 409 |
| GET | `/suggestions/versions/:id` | 历史版本只读详情 |
| POST | `/versions/:id/confirm` | 门店确认（幂等键）；旧版本 409、重复确认幂等 |
| GET | `/orders` · POST `/orders/:id/review` | 订单查询 · 生成复盘（幂等） |
| GET | `/reviews` · POST `/reviews/:id/entry` | 复盘查询 · 录入当日实绩（还原+归因+样本回流） |
| GET/POST | `/waste-records` | 报损单（窗口内结转重算/过窗存档） |
| GET/POST | `/stocktakes` | 盘点（以盘点为准、差异批次剔除训练样本） |
| GET/POST | `/shelf/rule-versions` | 保质期分组规则版本（GET 按日期取当时版本；POST 总部新建，生效日不得回写） |
| GET/POST | `/shelf/batches` | 批次台账（保质期分组、在库/在途/临期）· 登记批次（同批次号幂等） |
| POST | `/shelf/batches/:id/arrive` | 在途批次到货入库 |
| GET/POST | `/shelf/batch-stocktakes` | 批次盘点（以盘为准、差额独立账）· 提交（按批次+盘点时点幂等） |
| GET/POST | `/shelf/carryover` | 结转历史 · 执行结转（按门店+营业日+盘点时点幂等，成本归属按当时规则版本） |
| GET | `/shelf/reconciliation` | 按到货日对账差异（待复核） |
| POST | `/shelf/reconcile` | 执行对账（台账 / 结转 / 复盘口径） |
| POST | `/shelf/reconciliation/:id/resolve` | 复核差异单（总部） |
| GET | `/markdown` | 折价计划、折价需求与真实需求分列 |
| POST | `/markdown/plans` | 建临期折价计划（幂等键） |
| POST | `/markdown/plans/:id/entries` | 折价单（窗口内重算 / 过窗归档） |
| POST | `/reviews/:id/confirm` | 确认复盘（锁定口径，重算不追溯） |
| GET/POST | `/replays` · GET `/replays/:id` | 重算记录 · 按当时规则版本重算未确认区间（总部） |
